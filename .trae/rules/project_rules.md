# 项目规则文档

## 1. 知识传递机制

### 1.1 设计思路继承
- **核心文件**：`docs/经验教训/`目录下的复盘文档
- **继承机制**：后续AI系统必须首先阅读`docs/经验教训/`目录下的所有文档，理解前期AI的设计思路和决策过程
- **决策记录**：所有重大设计决策必须记录在`docs/经验教训/`目录中，包括决策原因、备选方案和最终选择
- **文件管理**：避免创建冗余文件，所有临时文件必须在任务完成后清理

### 1.2 系统连续性保障
- **统一入口**：`project_rules.md`作为新AI系统的统一入口文件，必须包含所有关键信息
- **版本控制**：使用Git版本控制确保文件历史可追溯
- **变更记录**：重要变更必须在文件头部添加变更日志

## 2. 核心场景与触发词

### 2.1 开发场景
- **触发词**："开发XXX"
- **功能**：启动新功能开发流程，包括需求分析、设计、编码和测试
- **流程**：方案评估 → 方案确认 → 执行 → 验收

### 2.2 备份场景
- **触发词**："备档"
- **功能**：执行完整三层备份（Git + 本地ZIP + 夸克网盘）
- **流程**：Git提交 → 本地ZIP备份 → 推送远程

### 2.3 发布场景
- **触发词**："发布"
- **功能**：执行发布流程，包括备份、测试和合并到main分支
- **流程**：最终备份 → 测试验证 → 合并到main → 推送远程

## 3. 系统架构与设计决策

### 3.1 系统架构
- **前端**：微信小程序原生开发
- **后端**：微信云开发（CloudBase）
- **数据库**：云数据库（NoSQL）
- **部署**：自动化脚本部署

### 3.2 核心设计决策
- **MCP工具优先**：任何情况下，只要MCP能够实现的功能，绝对不允许使用脚本替代
- **三层备份架构**：Git版本控制 + 本地ZIP备份 + 夸克网盘同步
- **分支管理策略**：main分支（稳定版） + v1分支（开发版） + feature分支（功能开发），详见13.2分支管理
- **文档管理体系**：统一的文档结构和审核机制

### 3.3 技术选型
- **开发语言**：JavaScript/TypeScript
- **云函数运行时**：Node.js 18.15
- **UI框架**：微信小程序原生组件
- **样式规范**：黑金配色（#0a0a0a + #D4B083）
