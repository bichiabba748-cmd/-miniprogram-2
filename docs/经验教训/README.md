## 最佳实践

1. **及时记录**：问题解决后24小时内记录，避免遗忘
2. **详细描述**：包含问题描述、定位过程、解决方案、经验教训
3. **分类清晰**：按类型、严重程度、模块分类
4. **标签管理**：使用标签方便检索（如：#前端 #数据库 #P0）
5. **定期回顾**：每周/每月回顾，梳理共性问题
6. **持续改进**：根据复盘结果优化流程和规范
7. **知识共享**：新人入职时学习历史问题复盘

## AI使用指南

### 如何使用这些文档

1. **开发前**：阅读相关模块的历史问题复盘，了解常见坑点
2. **开发中**：遇到类似问题时，先查阅历史复盘，避免重复犯错
3. **开发后**：新问题解决后，及时记录到本目录
4. **定期回顾**：每周回顾本周遇到的问题，总结经验

### AI角色使用规范

- **产品经理**：负责整理记录、分类归档、定期回顾
- **前端开发**：遇到前端问题时，先查阅本目录，解决后记录
- **后端开发**：遇到后端问题时，先查阅本目录，解决后记录
- **Git专家**：遇到版本控制问题时，先查阅本目录，解决后记录

### 关键经验

1. **角色体系要完整**：7角色体系（Visitor/Student/Anchor/Broker/Customer/Tenant/Admin）每个角色都要考虑到
2. **测试要覆盖所有角色**：不能只测试一个角色，要测试所有角色
3. **云函数逻辑要仔细检查**：特别是条件判断，容易遗漏某些情况
4. **添加详细日志**：帮助快速定位问题
5. **测试数据要唯一**：每次测试使用不同的手机号，避免数据重复
6. **代码逻辑要理解**：不要误判问题
7. **角色判断逻辑要完整**：确保所有角色都被包含在条件判断中
