# 001-角色管理架构

## 状态

✅ 已实施

## 背景

星火计划微信小程序需要支持多种用户角色，包括内部人员和外部客户，每种角色需要看到不同的界面和功能。为了确保系统的可扩展性和维护性，需要设计一个统一的角色管理架构。

## 决策

### 1. 角色体系设计

采用7+2角色体系，覆盖所有业务场景：

| 角色 | 代码 | 描述 | 权限级别 |
|------|------|------|----------|
| 访客 | visitor | 未加入星火计划 | 最低 |
| 学员 | student | 已加入星火计划，可学习 | 基础 |
| 主播 | anchor | 可提报文案/录客 | 核心 |
| 经纪人 | broker | 可提报/录客，按业务类型分化工具箱 | 核心 |
| 客户 | customer | 购房意向客户，隐藏TabBar | 外部 |
| 租客 | tenant | 已签约租户，独立页面体系 | 外部 |
| 管理员 | admin | 全权限+上帝模式 | 最高 |

**经纪人业务类型细分**：

| 业务类型 | 代码 | 描述 |
|---------|------|------|
| 租赁经纪人 | rental | 租赁业务经纪人 |
| 二手房经纪人 | trading | 二手房业务经纪人 |
| 新房经纪人 | new_house | 新房业务经纪人 |

### 2. 实现方式

#### 核心文件
- `miniprogram/utils/roleManager.js` - 角色管理核心类
- `miniprogram/pages/index/index.js` - 首页角色切换逻辑
- 云函数 `login` - 用户认证和角色分配

#### 关键设计

1. **角色存储**：
   - 使用 `wx.setStorageSync('userRole')` 本地存储角色信息
   - 使用 `app.globalData.userProfile` 存储用户详细信息

2. **角色判断**：
   - 提供 `RoleManager.getCurrentRole()` 方法获取当前角色
   - 提供 `RoleManager.hasPermission()` 方法判断权限

3. **业务类型分化**：
   - 经纪人角色按 `business_type` 分为租赁、二手房、新房
   - 通过 `businessType` 本地存储和用户 profile 获取

### 3. 角色切换逻辑

1. **登录时**：
   - 云函数 `login` 返回用户角色信息
   - 本地存储角色和业务类型

2. **页面加载时**：
   - 调用 `RoleManager.getCurrentRole()` 获取角色
   - 根据角色动态调整界面元素

3. **租户特殊处理**：
   - 租户角色自动重定向到租户首页
   - 隐藏TabBar，使用独立导航体系

### 4. 权限控制机制

采用基于角色的权限控制（RBAC）模型：

- **权限矩阵**：在 `PERMISSIONS` 对象中定义角色权限
- **权限检查**：使用 `RoleManager.hasPermission()` 方法
- **默认权限**：管理员默认拥有所有权限

### 5. 与其他模块的集成

1. **首页动态控制**：
   - 根据角色动态显示工具列表
   - 根据角色调整标题和UI元素
   - 控制TabBar显示/隐藏

2. **页面权限控制**：
   - 在页面加载时检查权限
   - 对无权限操作进行拦截

3. **云函数权限**：
   - 云函数中验证用户角色
   - 拒绝无权限的操作

## 影响

### 正面影响

1. **统一管理**：集中处理所有角色相关逻辑
2. **可扩展性**：易于添加新角色和权限
3. **代码复用**：避免重复的角色判断逻辑
4. **安全性**：统一的权限控制机制

### 风险

1. **复杂度**：角色逻辑集中可能增加维护复杂度
2. **性能**：频繁的角色检查可能影响性能
3. **兼容性**：角色体系变更可能影响现有功能

## 缓解措施

1. **模块化**：将角色逻辑封装到 `RoleManager` 类中
2. **缓存**：缓存角色信息，减少重复检查
3. **文档**：详细记录角色体系和权限矩阵
4. **测试**：为每种角色场景编写测试用例

### 核心API

1. **RoleManager.getCurrentRole()**
   - 获取当前用户角色
   - 返回：角色代码字符串

2. **RoleManager.hasPermission(permissionKey)**
   - 检查用户是否有指定权限
   - 参数：权限键名
   - 返回：布尔值

3. **RoleManager.setRole(roleCode)**
   - 设置用户角色
   - 参数：角色代码
   - 返回：布尔值（设置是否成功）

4. **RoleManager.getRoleInfo(roleCode)**
   - 获取角色详细信息
   - 参数：角色代码（可选，默认当前角色）
   - 返回：角色信息对象

## 未来扩展

### 可能的扩展点

1. **角色继承**：支持角色权限继承
2. **动态权限**：基于用户属性的动态权限
3. **权限组**：将多个权限组合为权限组
4. **角色转换**：定义角色间的转换规则

### 扩展建议

- 当添加新角色时，更新 `ROLES` 对象和权限矩阵
- 当添加新权限时，更新 `PERMISSIONS` 对象
- 保持 `RoleManager` 类的接口稳定
- 定期审查角色体系，确保符合业务需求
