# 003-权限控制矩阵

## 状态

✅ 已实施

## 背景

星火计划微信小程序需要对不同角色的用户进行权限控制，确保用户只能访问其权限范围内的功能和数据。为了实现统一、灵活的权限管理，需要设计一个权限控制矩阵。

## 决策

### 1. 权限控制架构

采用**基于角色的权限控制（RBAC）**模型，通过权限矩阵定义不同角色的访问权限。

#### 核心原则
- **最小权限**：每个角色只授予完成任务所需的最小权限
- **权限分离**：不同职责的权限分离，避免权限集中
- **统一管理**：集中管理所有权限定义和角色分配
- **可扩展性**：易于添加新权限和角色

### 2. 实现方式

#### 核心文件
- `miniprogram/utils/roleManager.js` - 权限控制核心类
- 云函数权限验证逻辑
- 页面权限检查逻辑

#### 关键设计

1. **权限矩阵定义**：
   - 在 `PERMISSIONS` 对象中定义所有权限
   - 每个权限对应一个允许的角色数组

2. **权限检查方法**：
   - 提供 `RoleManager.hasPermission()` 方法检查权限
   - 支持管理员默认拥有所有权限

3. **权限类型**：
   - **功能权限**：控制对功能的访问
   - **数据权限**：控制对数据的访问
   - **操作权限**：控制对操作的执行

### 4. 权限检查实现

#### 核心方法

```javascript
class RoleManager {
  // 核心判定：是否有某项权限
  static hasPermission(permissionKey) {
    const currentRole = this.getCurrentRole();
    const allowedRoles = PERMISSIONS[permissionKey] || [];
    // 自动容错：如果忘记配置admin，默认admin拥有所有权限 (除了特定的业务限制)
    if (currentRole === 'admin') return true; 
    return allowedRoles.includes(currentRole);
  }
}
```

### 5. 权限应用场景

#### 1. 页面访问控制

```javascript
// 页面加载时检查权限
onLoad() {
  if (!RoleManager.hasPermission('canViewStats')) {
    wx.showToast({ 
      title: '权限不足', 
      icon: 'none' 
    });
    wx.navigateBack();
    return;
  }
  // 正常加载页面
}
```

#### 2. 功能按钮控制

```javascript
// 按钮显示控制
<view class="btn" wx:if="{{hasSubmitPermission}}" bindtap="onSubmit">提报战绩</view>

// 权限检查
onLoad() {
  this.setData({
    hasSubmitPermission: RoleManager.hasPermission('canSubmitReport')
  });
}
```

#### 3. 云函数权限验证

```javascript
// 云函数权限验证
exports.main = async (event, context) => {
  const { userInfo } = context;
  const role = await getUserRole(userInfo.openId);
  
  if (!hasPermission(role, 'canSubmitReport')) {
    return {
      success: false,
      error: '权限不足'
    };
  }
  
  // 执行提报逻辑
};
```

#### 4. 数据访问控制

```javascript
// 数据查询权限控制
const getArticles = async (role) => {
  let query = db.collection('articles');
  
  // 根据权限控制数据访问
  if (!RoleManager.hasPermission('canViewArtContent')) {
    // 只返回标题，不返回内容
    query = query.field({ title: true, category: true });
  }
  
  return query.get();
};
```

### 6. 权限管理流程

#### 1. 权限定义

1. 在 `PERMISSIONS` 对象中添加新权限
2. 定义允许访问的角色数组
3. 更新相关文档

#### 2. 权限分配

1. 通过角色分配权限（间接）
2. 特殊情况下通过用户属性分配权限（直接）

#### 3. 权限检查

1. 在页面加载时检查权限
2. 在功能执行前检查权限
3. 在数据访问前检查权限
4. 在云函数执行前检查权限

### 7. 权限控制最佳实践

#### 1. 前端权限控制

- **页面级权限**：在页面 `onLoad` 时检查权限
- **功能级权限**：在功能执行前检查权限
- **UI级权限**：根据权限控制UI元素显示
- **跳转级权限**：在导航前检查权限

#### 2. 后端权限控制

- **云函数权限**：在云函数入口检查权限
- **数据库权限**：使用数据库安全规则
- **API权限**：在API接口层面检查权限
- **操作日志**：记录权限相关操作

#### 3. 安全考虑

- **前端权限只是辅助**：后端必须有完整的权限验证
- **防止权限提升**：验证用户角色的真实性
- **权限边界清晰**：明确各角色的权限边界
- **定期权限审查**：定期检查权限配置的合理性

## 影响

### 正面影响

1. **安全性**：防止未授权访问
2. **可维护性**：集中管理权限定义
3. **可扩展性**：易于添加新权限和角色
4. **清晰度**：明确各角色的权限边界
5. **合规性**：满足数据保护要求

### 风险

1. **复杂度**：权限矩阵可能变得复杂
2. **性能**：频繁的权限检查可能影响性能
3. **维护**：权限变更需要更新多个地方
4. **测试**：需要测试所有权限场景

## 缓解措施

1. **模块化**：将权限逻辑封装到 `RoleManager` 类中
2. **缓存**：缓存权限检查结果，减少重复计算
3. **文档**：详细记录权限定义和使用方法
4. **测试**：为每种权限场景编写测试用例
5. **自动化**：使用工具自动生成权限文档和测试

## 实施细节
