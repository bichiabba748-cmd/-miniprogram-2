# 007-智能体协作体系

## 状态

✅ 已实施

## 背景

星火计划小程序开发涉及多个专业领域，包括前端开发、后端开发、版本控制和产品管理。为了提高开发效率、明确职责分工、降低协作复杂度，需要建立一个清晰的智能体协作体系。

## 决策

### 1. 智能体角色设计

采用4角色协作体系，覆盖开发全流程：

| 角色 | 职责范围 | MCP工具配置 |
|------|---------|------------|
| Git专家 | 版本控制、分支管理、备份策略 | GitHub MCP工具 |
| 前端开发 | 小程序页面、组件、样式 | 文件操作工具 |
| 后端开发 | 云函数、数据库、API | 文件操作工具 |
| 产品经理 | 需求分析、规格文档、验收标准 | GitHub MCP工具 |

### 2. 角色职责定义

#### Git专家
- 分支管理（main/v1分支切换）
- 代码合并和冲突解决
- 备份策略执行（夸克网盘 + 本地ZIP + Git版本）
- 版本发布管理

#### 前端开发
- 小程序页面开发
- 组件编写和维护
- 样式实现（遵循黑金配色）
- 用户体验优化

#### 后端开发
- 云函数开发和部署
- 数据库设计和维护
- API接口实现
- 错误日志记录

#### 产品经理
- 需求分析和拆解
- 编写和更新规格说明书（PRD）
- 管理开发进度（progress.md）
- 文档一致性检查
- 功能验收
- 更新协作规则文档

### 3. 协作流程

#### 开发流程
1. **方案评估**：产品经理读取文档 → 分析现状 → 设计方案 → 输出评估报告
2. **方案确认**：产品经理提交修改方案 → 用户确认后开始执行
3. **执行阶段**：Git专家备份 → 前端/后端开发修改代码 → 自测 → 输出结果
4. **验收阶段**：用户查看效果 → 提出修改意见 → 产品经理验收通过

#### 责任分配

| 任务 | 责任人 |
|------|--------|
| 代码开发与修改 | 前端开发 / 后端开发 |
| 方案设计与确认 | 产品经理 |
| 功能验收与测试 | 用户 |
| 文档更新与维护 | 产品经理 |
| 备份与版本管理 | Git专家 |

### 4. 沟通机制

- 前端/后端开发完成后，通知产品经理验收
- 产品经理验收通过后，通知Git专家合并到main
- Git专家合并前，确保文档已更新

### 5. 提示词管理

各角色提示词文件位于 `docs/协作宪法/prompts/` 目录：
- `git_expert.md` - Git专家提示词
- `frontend_developer.md` - 前端开发提示词
- `backend_developer.md` - 后端开发提示词
- `product_manager.md` - 产品经理提示词

## 影响

### 正面影响

1. **职责清晰**：每个角色专注自己的职责范围
2. **效率提升**：减少角色切换和决策冲突
3. **质量保障**：产品经理负责文档管理和一致性检查
4. **协作顺畅**：明确的沟通机制和责任分配

### 风险

1. **角色切换**：需要在不同角色间切换，可能增加上下文切换成本
2. **依赖关系**：角色间存在依赖关系，可能影响开发效率
3. **学习成本**：需要理解各角色的职责和协作机制

## 缓解措施

1. **提示词完善**：为每个角色编写详细的提示词
2. **文档同步**：确保所有相关文档同步更新
3. **流程优化**：定期优化协作流程，提高效率
4. **沟通机制**：建立清晰的沟通机制，减少误解

### 核心原则

1. **职责分离**：每个角色专注自己的职责范围
2. **协作优先**：角色间协作优先于个人决策
3. **文档同步**：文档更新与代码开发同步进行
4. **质量保障**：产品经理负责验收和质量保障

## 未来扩展

### 可能的扩展点

1. **角色细化**：根据项目需要细化角色职责
2. **自动化工具**：引入自动化工具提高协作效率
3. **性能监控**：监控协作效率，持续优化流程
4. **知识库**：建立角色知识库，降低学习成本
