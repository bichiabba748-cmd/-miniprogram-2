# 架构决策记录 (ADR): 收藏功能存储方案

## 状态
已接受

## 背景
收藏功能是小程序的核心功能之一，用户需要能够收藏感兴趣的文案和内容，并在收藏页面查看和管理这些收藏项。

### 初始方案
最初设计采用云函数+数据库存储方案：
- 使用 `toggleCollection` 云函数处理收藏/取消收藏操作
- 使用 `getUserCollections` 云函数获取用户收藏列表
- 数据存储在 `user_collections` 集合中

### 遇到的问题
1. **云函数调用失败**：在测试过程中，云函数调用经常失败
2. **数据库权限问题**：`user_collections` 集合的权限配置遇到困难，无法正确设置
3. **网络依赖**：收藏操作依赖网络连接，离线时无法使用
4. **响应速度**：云函数调用有网络延迟，影响用户体验

## 决策
### 选择方案
采用**本地存储方案**实现收藏功能

### 技术实现
1. **数据存储**：使用 `wx.getStorageSync` 和 `wx.setStorageSync` 进行本地存储
2. **数据结构**：使用简单数组存储收藏项，每个收藏项包含：
   - `articleId`: 文章ID
   - `articleTitle`: 文章标题
   - `status`: 状态（'collected' 或 'shooting'）
   - `createdAt`: 创建时间
   - `updatedAt`: 更新时间
3. **管理逻辑**：创建 `CollectionManager` 对象统一管理收藏操作
4. **跨页面同步**：通过本地存储实现页面间收藏状态同步

### 适用文件
- `miniprogram/pages/art/art.js`：文案库页面的收藏功能
- `miniprogram/pages/collections/collections.js`：收藏管理页面

## 影响
### 积极影响
1. **可靠性**：避免了云函数调用失败和数据库权限问题
2. **用户体验**：离线可用，响应速度快
3. **实现简单**：代码量减少，逻辑清晰
4. **无额外成本**：不产生云函数调用费用

### 消极影响
1. **跨设备同步**：收藏数据仅存储在本地，无法跨设备同步
2. **数据持久化**：清除小程序缓存会丢失收藏数据
3. **数据分析**：无法进行服务端数据分析

## 适用规模
- **用户规模**：适合 100-500 人的经纪人团队使用
- **数据量**：每个用户收藏数据量有限，本地存储完全足够
- **并发访问**：不存在并发访问问题，每个用户数据独立

## 未来规划
### 长期方案
待用户规模稳定后，可考虑迁移到云函数方案，实现：
1. **跨设备同步**：用户可在不同设备上查看相同的收藏数据
2. **数据备份**：收藏数据安全存储在云端
3. **数据分析**：基于收藏数据进行用户行为分析
4. **高级功能**：如收藏分享、收藏推荐等

### 迁移策略
1. 实现云函数方案
2. 添加数据迁移功能，将用户本地收藏数据同步到云端
3. 双写模式过渡，确保数据一致性
4. 完全切换到云函数方案

## 结论
本地存储方案是当前阶段的最佳选择，它解决了云函数方案遇到的问题，提供了可靠的收藏功能，同时为未来的扩展留下了空间。
