# 004-文件结构规范

## 状态

✅ 已实施

## 背景

星火计划微信小程序开发过程中，需要确保文件结构的一致性和合理性，避免不必要的文件创建，提高代码的可维护性和可读性。为了指导未来的开发过程，需要制定一套文件结构规范。

## 决策

### 1. 总体文件结构

采用微信小程序标准文件结构，同时根据业务需求进行合理组织。

### 2. 文件创建原则

#### 核心原则
- **必要性**：只有在确实需要时才创建新文件
- **一致性**：遵循现有的文件命名和结构规范
- **模块化**：将相关功能组织到同一目录
- **可维护性**：确保文件结构清晰易懂

#### 具体规则

1. **页面文件创建**：
   - **优先考虑**：复用现有页面，通过动态控制实现不同功能
   - **仅在必要时创建**：当功能差异很大，无法通过动态控制实现时
   - **命名规范**：使用小写字母和连字符，如 `broker-rental`

2. **组件文件创建**：
   - **优先考虑**：使用现有组件，通过属性控制不同行为
   - **仅在必要时创建**：当现有组件无法满足需求时
   - **命名规范**：使用 PascalCase，如 `RoleManager`

3. **工具类文件创建**：
   - **优先考虑**：扩展现有工具类
   - **仅在必要时创建**：当功能独立，与现有工具类无关联时
   - **命名规范**：使用 camelCase，如 `roleManager.js`

4. **云函数创建**：
   - **优先考虑**：复用现有云函数，通过参数控制不同行为
   - **仅在必要时创建**：当功能独立，与现有云函数无关联时
   - **命名规范**：使用 camelCase，如 `getLeaderboard`

### 3. 目录结构规范

#### 1. 页面目录

- **按功能模块组织**：将相关页面组织到同一目录
- **按角色组织**：如 `tenant/` 和 `broker-rental/`
- **命名规范**：使用小写字母和连字符
- **文件组织**：每个页面包含 `.js`、`.wxml`、`.wxss`、`.json` 文件

#### 2. 组件目录

- **按功能组织**：将相关组件组织到同一目录
- **命名规范**：使用 PascalCase
- **文件组织**：每个组件包含 `.js`、`.wxml`、`.wxss`、`.json` 文件

#### 3. 工具类目录

- **按功能组织**：将相关工具类组织到同一目录
- **命名规范**：使用 camelCase
- **文件组织**：每个工具类一个文件，包含相关功能

#### 4. 云函数目录

- **按功能组织**：将相关云函数组织到同一目录
- **命名规范**：使用 camelCase
- **文件组织**：每个云函数一个目录，包含 `index.js` 和 `package.json`

#### 5. 文档目录

- **按类型组织**：将相关文档组织到同一目录
- **命名规范**：使用中文，清晰表达文档类型
- **文件组织**：每个文档一个文件，包含相关内容

### 4. 文件命名规范

#### 1. 页面文件

- **目录名**：小写字母 + 连字符，如 `broker-rental`
- **文件名**：与目录名一致，如 `leaderboard.js`
- **命名原则**：简洁明了，表达页面功能

#### 2. 组件文件

- **目录名**：PascalCase，如 `RoleSelector`
- **文件名**：与目录名一致，如 `RoleSelector.js`
- **命名原则**：表达组件功能，使用语义化名称

#### 3. 工具类文件

- **文件名**：camelCase，如 `roleManager.js`
- **命名原则**：表达工具类功能，使用语义化名称

#### 4. 云函数文件

- **目录名**：camelCase，如 `getLeaderboard`
- **文件名**：固定为 `index.js`
- **命名原则**：表达云函数功能，使用语义化名称

#### 5. 文档文件

- **文件名**：中文 + 编号，如 `001-角色管理架构.md`
- **命名原则**：清晰表达文档内容，使用语义化名称

### 5. 文件创建流程

#### 1. 页面文件创建流程

1. **需求分析**：分析功能需求
2. **现有文件检查**：检查是否有现有页面可以复用
3. **动态控制评估**：评估是否可以通过动态控制实现
4. **文件创建**：如果确实需要，创建新页面文件
5. **配置更新**：更新 `app.json` 中的页面配置
6. **文档更新**：更新相关文档

#### 2. 组件文件创建流程

1. **需求分析**：分析组件需求
2. **现有组件检查**：检查是否有现有组件可以复用
3. **组件扩展评估**：评估是否可以通过扩展现有组件实现
4. **文件创建**：如果确实需要，创建新组件文件
5. **文档更新**：更新相关文档

#### 3. 工具类文件创建流程

1. **需求分析**：分析工具类需求
2. **现有工具类检查**：检查是否有现有工具类可以复用
3. **工具类扩展评估**：评估是否可以通过扩展现有工具类实现
4. **文件创建**：如果确实需要，创建新工具类文件
5. **文档更新**：更新相关文档

#### 4. 云函数创建流程

1. **需求分析**：分析云函数需求
2. **现有云函数检查**：检查是否有现有云函数可以复用
3. **云函数扩展评估**：评估是否可以通过扩展现有云函数实现
4. **文件创建**：如果确实需要，创建新云函数文件
5. **配置更新**：更新云函数配置
6. **文档更新**：更新相关文档

### 6. 避免不必要的文件创建

#### 1. 首页动态控制

- **原则**：通过动态控制实现不同角色的首页，不创建多个首页文件
- **实现**：使用 `roleManager.js` 和条件判断控制界面
- **优势**：减少代码冗余，提高维护性

#### 2. 组件复用

- **原则**：通过属性控制实现组件的不同行为，不创建多个相似组件
- **实现**：使用组件属性和条件渲染
- **优势**：减少组件数量，提高一致性

#### 3. 工具类复用

- **原则**：通过方法扩展实现工具类的新功能，不创建多个相似工具类
- **实现**：在现有工具类中添加新方法
- **优势**：集中管理相关功能，提高可维护性

#### 4. 云函数复用

- **原则**：通过参数控制实现云函数的不同行为，不创建多个相似云函数
- **实现**：使用 `action` 参数控制云函数行为
- **优势**：减少云函数数量，降低维护成本

### 7. 代码复用策略

#### 1. 页面级复用

- **模板复用**：使用 `template` 实现页面模板复用
- **组件复用**：使用自定义组件实现功能复用
- **逻辑复用**：使用 `behaviors` 实现页面逻辑复用

#### 2. 组件级复用

- **属性控制**：通过属性控制组件行为
- **插槽使用**：使用 `slot` 实现组件内容定制
- **事件传递**：使用事件实现组件与页面通信

#### 3. 工具类级复用

- **静态方法**：使用静态方法实现工具类复用
- **类继承**：使用类继承实现工具类扩展
- **混入**：使用混入实现工具类功能组合

#### 4. 云函数级复用

- **参数控制**：通过参数控制云函数行为
- **模块化**：将云函数逻辑拆分为模块
- **共享代码**：使用共享代码实现云函数复用

### 8. 代码组织最佳实践

#### 1. 页面代码组织

- **逻辑分离**：将页面逻辑拆分为多个方法
- **数据管理**：使用 `data` 和 `setData` 管理页面数据
- **生命周期**：合理使用页面生命周期函数
- **事件处理**：集中管理事件处理函数

#### 2. 组件代码组织

- **属性定义**：清晰定义组件属性
- **数据管理**：使用 `properties` 和 `data` 管理组件数据
- **生命周期**：合理使用组件生命周期函数
- **方法组织**：将组件方法按功能分组

#### 3. 工具类代码组织

- **功能分组**：将工具类方法按功能分组
- **静态方法**：优先使用静态方法
- **错误处理**：添加适当的错误处理
- **文档注释**：添加详细的文档注释

#### 4. 云函数代码组织

- **逻辑分离**：将云函数逻辑拆分为多个函数
- **错误处理**：添加适当的错误处理
- **日志记录**：添加必要的日志记录
