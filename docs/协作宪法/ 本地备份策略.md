# 本地备份策略（云盘同步版）

> **核心目标**：防止代码丢失或改坏，随时能恢复到稳定版本
> 

---

## 1. 三层备份架构（网盘+Git）

### 第一层：夸克网盘自动同步（最新版本）

- **同步内容**：miniprogram2整个文件夹
- **触发机制**：有文件更新就自动备份
- **用途**：随时恢复到最新状态
- **优势**：无需手动操作，改完就自动备份

### 第二层：项目内置备份（历史版本）

- **备份内容**：完整项目文件夹（miniprogram + cloudfunctions + docs）
- **存放位置**：项目根目录 `backups/` 文件夹
- **备份格式**：ZIP压缩文件
- **命名方式**：时间戳格式 `backup-2026-02-03T12-34-56-789Z`
- **保留数量**：自动保留最新7个备份，删除旧备份
- **触发时机**：
    - 每天开工前（如果昨天有改动）
    - 重大里程碑完成后（P1通电/P3核心页等）
    - 每日开发结束时（配合Git推送）
    - 确保是能用的版本才备份，没修好的不备份
- **用途**：回溯历史稳定版本
- **执行方式**：运行 `.\push-backup.ps1` 脚本自动备份

### 第三层：Git版本控制（远程存储）

- **仓库信息**：日华里miniprogram-2
- **分支策略**：main（主分支）
- **提交规则**：每次开发完成后提交，包含清晰的提交信息
- **推送时机**：每日开发结束时自动推送
- **AI职责**：帮助执行Git操作（提交、推送等）
- **优势**：远程存储安全、版本追溯精确、团队协作无缝

---

## 2. 日常操作 SOP

### 早上开工前

1. 如果昨天有改动 → 复制miniprogram2到桌面 → 命名为"miniprogram2_日期"
2. 打开微信开发者工具开始干活
3. 夸克网盘自动同步最新改动（无需操作）

### 遇到问题需要回退

**场景1：刚才改坏了（最近1小时内）**

- 从夸克网盘找最近的自动备份版本 → 复制回去

**场景2：需要回到昨天或更早**

- 从桌面历史版本找对应日期 → 复制回去

### 完成里程碑

1. 确认功能正常、能正常运行
2. 复制到桌面存档（命名"miniprogram2_P1通电_20260124"）
3. 在Notion代码页面记录改动日志

---

## 3. Notion改动日志规则

### 触发条件

代码有重大更新，需要在Notion代码仓库记录

### 记录位置

对应代码页面顶部

### 格式

```
## 更新日志
- **2026-01-24**：P1云端通电完成，users/articles/clients集合创建
- **2026-01-23**：规格书终版确认，字段名对齐
```

### 保留规则

最多保留最近5条记录，超过则删除最旧的

## 4. 三方协作的备份职责

| 角色 | 备份职责 | 说明 |
| --- | --- | --- |
| **你（总指挥）** | 云盘自动同步 + 桌面手动存档 + Notion日志 | 双层保险，防止代码丢失 |
| **Trae** | 配置云函数error logs | 方便上线后排查bug |
| **我（总参谋）** | 更新Notion代码页面时加日志记录 | 保持文档与代码同步 |

## 战略价值

1. **Notion（战略部）**：存图纸、进度、契约
2. **夸克网盘（云端库）**：自动保持最新版本
3. **桌面存档（历史库）**：手动存历史稳定版本
4. **GitHub（远程库）**：安全存储代码，提供版本控制
5. **Cursor/Trae（施工队）**：按标准干活，改坏了随时能救回来

### 三层备份架构的优势

- **安全性**：本地+云端+远程三重保障，彻底防止代码丢失
- **便捷性**：AI自动执行Git操作，0学习成本
- **可靠性**：多版本备份，随时可回退到任意稳定版本
- **扩展性**：为未来团队协作和项目迭代做好准备
