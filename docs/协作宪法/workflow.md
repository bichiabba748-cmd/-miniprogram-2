# 工作流协议（workflow.md）

## 🤖 智能体协作体系

### 角色分工
- **Git专家** - 版本控制、分支管理、备份策略
- **前端开发** - 小程序页面、组件、样式
- **后端开发** - 云函数、数据库、API
- **产品经理** - 需求分析、规格文档、验收标准、文档管理

### 协作原则
- 每个智能体专注自己的职责范围
- 产品经理负责文档管理和一致性检查
- Git专家负责版本控制和合并
- 前端/后端专注代码实现

### 沟通机制
- 前端/后端开发完成后，通知产品经理验收
- 产品经理验收通过后，通知Git专家合并到main
- Git专家合并前，确保文档已更新

## 📋 完整场景协议

### 1. 开工流程

**触发词**："开始做XXX"

**责任人**：产品经理（方案设计）、前端开发/后端开发（代码开发）

**详细步骤**：
1. **检查分支状态**：确保当前在 v1 分支（装修间）
2. **创建开发环境**：如果需要，创建对应的功能文件夹和文件结构
3. **读取相关文档**：读取规格书、数据库模型、接口契约等相关文档
4. **设计方案**：根据需求设计具体的实现方案
5. **等待确认**：提交方案给用户确认后开始执行

**输出格式**：
```
✅ 开工流程启动：开始开发 XXX 功能
📁 当前分支：v1（装修间）
📚 已读取相关文档：[文档列表]
📋 开发方案：[简要方案描述]
```

### 2. 暂存流程

**触发词**："暂存"/"备份"/"Save"

**责任人**：Git专家（备份）、产品经理（文档更新）

**详细步骤**：
1. **检查代码状态**：确保所有修改都已保存
2. **执行 Git 提交**：提交当前修改到 v1 分支
3. **创建 ZIP 备份**：将当前项目压缩为 ZIP 文件，保存到 backup 文件夹
4. **清理备份**：检查 backup 文件夹，保留最近 7 个版本的备份
5. **更新文档**：自动检查并更新相关文档（开发进度、数据库模型、接口文档）

**输出格式**：
```
✅ 暂存流程完成：已保存 XXX 功能进度
📁 Git 提交：[提交信息]
💾 ZIP 备份：backup/backup-YYYY-MM-DD-HH-mm-SS.zip
📚 已更新文档：[文档列表]
```

### 3. 废弃流程

**触发词**："重来"/"瞎了"/"Abort"

**责任人**：Git专家（回滚）

**详细步骤**：
1. **确认操作**：确认用户要废弃当前修改
2. **回滚代码**：将代码回滚到最近一次暂存的状态
3. **清理环境**：删除不需要的临时文件和文件夹
4. **重置状态**：重置开发环境到干净状态

**输出格式**：
```
✅ 废弃流程完成：已重置到最近暂存状态
📁 当前分支：v1（装修间）
🔄 已回滚修改：[回滚信息]
```

### 4. 发布流程

**触发词**："发布"/"收工"/"Release"

**责任人**：产品经理（验收）、Git专家（合并推送）

**详细步骤**：
1. **最终检查**：检查代码质量、功能完整性、文档一致性
2. **执行 Git 提交**：提交最终修改到 v1 分支
3. **创建 ZIP 备份**：将当前项目压缩为 ZIP 文件，保存到 backup 文件夹
4. **清理备份**：检查 backup 文件夹，保留最近 7 个版本的备份
5. **更新文档**：自动检查并更新相关文档（开发进度、数据库模型、接口文档）
6. **合并到 main**：将 v1 分支的修改合并到 main 分支（展厅）
7. **推送 Git**：推送 main 分支和 v1 分支到远程仓库

**输出格式**：
```
✅ 发布流程完成：XXX 功能已发布
📁 已合并到 main 分支（展厅）
📤 已推送 Git 远程仓库
💾 ZIP 备份：backup/backup-YYYY-MM-DD-HH-mm-SS.zip
📚 已更新文档：[文档列表]
```

## 📖 Git 命令参考

### 分支管理
```bash
# 查看当前分支
git branch

# 切换到 v1 分支
git checkout v1

# 创建并切换到新分支
git checkout -b feature/xxx

# 合并分支到当前分支
git merge v1
```

### 提交与推送
```bash
# 查看修改状态
git status

# 添加修改
git add .

# 提交修改
git commit -m "[功能] 完成 XXX 功能开发"

# 推送分支到远程仓库
git push origin v1

# 推送 main 分支到远程仓库
git push origin main
```

### 回滚操作
```bash
# 查看提交历史
git log --oneline

# 回滚到指定提交（使用完整哈希值）
git reset --hard 446567e855bf7df2da9058c3292e214115160a81

# 撤销工作区修改
git checkout .
```

## 🔄 自动化触发机制

### 文档更新触发
- **代码修改后**：自动检查是否涉及接口/数据库，如有则更新对应文档
- **功能完成后**：自动更新 `docs/开发进度/progress.md` 进度
- **发布前**：强制检查并更新 `docs/数据库模型/数据库模型 (DB Schema).md` 和 `docs/接口文档/接口契约 (Contracts).md`

### 备份触发
- **暂存时**：触发 Git 提交 + ZIP 备份
- **发布时**：触发 Git 提交 + ZIP 备份 + Git 推送

### 提醒机制
- **文档未更新**：当检测到代码变更但对应文档未更新时，主动提示
- **备份过期**：当检测到超过 24 小时未备份时，主动提示

## 📝 责任分配

| 任务 | 责任人 |
|------|--------|
| 代码开发与修改 | 前端开发 / 后端开发 |
| 方案设计与确认 | 产品经理 |
| 功能验收与测试 | 用户 |
| 文档更新与维护 | 产品经理 |
| 备份与版本管理 | Git专家 |

## 🎯 验收标准

### 功能验收
- ✅ 代码编译通过，无语法错误
- ✅ 功能符合需求规格，运行正常
- ✅ 界面风格符合黑金配色要求
- ✅ 响应速度流畅，无明显卡顿

### 文档验收
- ✅ 开发进度文档已更新
- ✅ 数据库模型文档已同步
- ✅ 接口契约文档已更新
- ✅ 所有文档引用关系正确

### 备份验收
- ✅ Git 分支状态正确
- ✅ ZIP 备份文件已创建
- ✅ 夸克网盘同步正常
- ✅ 最近 7 个版本的备份已保留

## 🔧 问题处理

### 常见问题
1. **Git 命令失败**：检查 Git 配置和网络连接
2. **备份创建失败**：检查 backup 文件夹权限和磁盘空间
3. **文档更新失败**：检查文档文件权限和路径

### 解决方案
1. **Git 配置问题**：重新配置 Git 用户信息和远程仓库
2. **备份权限问题**：确保 backup 文件夹有写入权限
3. **文档路径问题**：检查文档文件是否存在，路径是否正确

## 📅 维护机制

### 定期检查
- **每日检查**：检查备份状态、文档一致性
- **每周检查**：检查分支状态、代码质量
- **每月检查**：检查备份策略有效性、文档体系完整性

### 方案更新
- 根据实际使用情况调整工作流细节
- 记录方案变更历史，确保可追溯性
- 定期优化自动化触发机制，提高效率
