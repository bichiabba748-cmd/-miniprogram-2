# 备份策略（backup_strategy.md）

## 🤖 智能体协作体系

### 角色分工
- **Git专家** - 负责三层备份的执行和管理
- **产品经理** - 负责文档一致性检查和更新
- **前端开发/后端开发** - 负责代码开发和修改

### 协作机制
- 前端/后端开发完成后，通知产品经理验收
- 产品经理验收通过后，通知Git专家执行备份
- Git专家负责执行三层备份（夸克网盘 + 本地ZIP + Git版本）

---

## 🔒 三层备份架构

### 1. 第一层：夸克网盘自动备份

**执行方式**：夸克网盘自动同步
**触发时机**：文件变更时自动同步
**同步目录**：整个项目根目录
**保留策略**：云盘自动版本管理
**优势**：实时同步，无需手动操作，可跨设备访问
**注意事项**：确保夸克网盘客户端保持运行状态

### 2. 第二层：本地 ZIP 备份

**执行方式**：自动化 ZIP 压缩
**触发时机**：
- 触发词 "暂存"/"备份"/"Save" 时
- 触发词 "发布"/"收工"/"Release" 时
**存储位置**：`backup` 文件夹
**命名规范**：`backup-YYYY-MM-DD-HH-mm-SS.zip`
**保留策略**：保留最近 7 个版本的备份
**备份内容**：
- 所有项目文件
- 不包含 `backup` 文件夹（避免无限循环）
- 不包含 `node_modules` 等依赖文件夹（节省空间）

### 3. 第三层：Git 版本控制

**执行方式**：分布式版本控制
**触发时机**：
- 触发词 "暂存"/"备份"/"Save" 时（Git 提交）
- 触发词 "发布"/"收工"/"Release" 时（Git 推送）
**存储位置**：GitHub 远程仓库
**分支策略**：
- `main` 分支（展厅）：黄金版本/对外发布状态
- `v1` 分支（装修间）：日常施工现场/开发分支
**保留策略**：永久保留完整版本历史
**优势**：可追溯每一次修改，支持分支管理和代码审查

## 📁 备份目录结构

```
project/
├── backup/                  # 本地 ZIP 备份文件夹
│   ├── backup-2026-02-04-13-45-30.zip  # 备份文件 1
│   ├── backup-2026-02-04-14-20-15.zip  # 备份文件 2
│   └── ...                  # 最多保留 7 个版本
├── .git/                   # Git 版本控制文件夹
├── docs/                   # 文档文件夹
├── miniprogram/            # 小程序源代码
└── other-files/            # 其他项目文件
```

## 🚀 自动化备份流程

### 暂存时的备份流程
1. **代码检查**：确保所有修改都已保存
2. **Git 提交**：提交当前修改到 v1 分支
3. **ZIP 备份**：创建项目压缩包，保存到 backup 文件夹
4. **备份清理**：检查 backup 文件夹，删除超过 7 个的旧备份
5. **文档更新**：自动检查并更新相关文档

### 发布时的备份流程
1. **最终检查**：检查代码质量、功能完整性、文档一致性
2. **Git 提交**：提交最终修改到 v1 分支
3. **ZIP 备份**：创建项目压缩包，保存到 backup 文件夹
4. **备份清理**：检查 backup 文件夹，删除超过 7 个的旧备份
5. **文档更新**：自动检查并更新相关文档
6. **分支合并**：将 v1 分支的修改合并到 main 分支
7. **Git 推送**：推送 main 分支和 v1 分支到远程仓库

## 🔄 备份恢复流程

### 从 ZIP 备份恢复
1. **选择备份**：从 backup 文件夹选择需要的备份文件
2. **解压文件**：将备份文件解压到项目目录
3. **覆盖文件**：确认覆盖现有文件
4. **检查状态**：检查项目状态是否正常

### 从 Git 恢复
1. **查看历史**：使用 `git log --oneline` 查看提交历史
2. **选择版本**：找到需要恢复的提交 ID
3. **执行恢复**：使用 `git reset --hard [commit-id]` 恢复到指定版本
4. **检查状态**：检查项目状态是否正常

### 从夸克网盘恢复
1. **打开夸克网盘**：登录夸克网盘客户端
2. **找到文件**：浏览到同步的项目文件夹
3. **下载文件**：下载需要恢复的文件到本地
4. **覆盖文件**：确认覆盖现有文件
5. **检查状态**：检查项目状态是否正常

## 📊 备份验证

### 定期检查
- **每日检查**：检查 backup 文件夹是否有最新备份
- **每周检查**：验证 Git 分支状态和远程仓库同步情况
- **每月检查**：测试备份恢复流程，确保备份有效性

### 验证内容
1. **备份文件完整性**：检查 ZIP 备份文件是否完整可解压
2. **Git 同步状态**：检查本地分支与远程仓库是否同步
3. **夸克网盘状态**：检查云盘同步是否正常，无同步错误
4. **恢复测试**：定期测试从备份恢复项目的流程

## 🔒 安全注意事项

1. **敏感信息**：确保备份文件不包含敏感信息（如 API 密钥、密码等）
2. **存储安全**：确保本地备份和云盘备份的存储设备安全可靠
3. **权限控制**：设置合理的文件权限，防止未授权访问
4. **网络安全**：确保 Git 远程仓库和云盘账户的安全，使用强密码和两步验证

## 📝 备份策略维护

### 策略更新
- **每月评估**：评估备份策略的有效性，根据实际情况调整
- **版本管理**：记录备份策略的变更历史，确保可追溯性
- **培训更新**：当备份策略变更时，及时更新相关文档和培训内容

### 问题处理
1. **备份失败**：检查备份文件夹权限、磁盘空间和网络连接
2. **同步错误**：检查夸克网盘客户端状态和网络连接
3. **版本冲突**：使用 Git 合并工具解决版本冲突，确保代码一致性

## 🎯 备份策略目标

- **数据安全**：确保项目数据不会丢失
- **版本可控**：所有修改都有记录，可随时追溯和恢复
- **操作便捷**：自动化备份流程，减少手动操作
- **跨设备访问**：通过云盘同步，实现跨设备开发
- **发布安全**：确保 main 分支始终保持可发布状态

---

**说明**：本备份策略是项目数据安全的重要保障，所有开发活动必须严格遵循本策略。
